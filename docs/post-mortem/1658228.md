# AB#1658228

## Executive Summary

Phase 1 gave the team's AI tools a set of coding standards distilled from post-mortems. That set only stays useful if new lessons keep reaching it, and today that depends on someone remembering to add them. Phase 2a — [AB#1658228](https://itsals.visualstudio.com/E_Retain_Content/_workitems/edit/1658228) — builds the piece that removes that dependency: a new skill, **capture-standard**, that runs while a release is being prepared. It reads the post-mortems the release carries, turns their lessons into proposed rules, checks them against each other and against the existing rules, shows the result, and after one confirmation opens a single pull request for review plus a ticket to make sure someone reviews it.

The skill is built and up for review as [PR #60](https://github.com/AlaskaAirlines/auro-ai/pull/60). Everything up to the confirmation has been run against a real release, twice, without writing anything. The final step — actually opening the pull request and the review ticket — has deliberately not been run yet; that is the first job of Phase 2b ([AB#1658229](https://itsals.visualstudio.com/E_Retain_Content/_workitems/edit/1658229)).

After the first trial proposed fifteen new rules from a single release, the bar for what counts as a rule was raised so the standards stay small and stable instead of growing with every release.

## The Problem

The coding standards are only as good as the lessons in them. Post-mortems keep being written, but nothing moved their lessons into the standards — it relied on someone remembering, release after release, which is exactly the kind of step that gets skipped. The organisation also will not run an AI model unattended in CI, so the capture could not simply be automated on every release.

The agreed shape was a skill that a person runs as part of preparing a release, alongside release notes. It had to be safe to run (nothing written without a clear yes), safe to re-run (no duplicate pull requests or tickets), and it must never hold up a release if it fails.

## Root Cause

There was no tooling between a component repo's `docs/post-mortem/<id>.md` files and the `auro-ai` rules corpus. Grounding the parent TRD against the real corpus (#57 §2) also showed the problem was harder than assumed:

- **Post-mortems use many heading shapes, not one.** The parent counted "27 of 66 with no learnings section" by searching for `## Learnings` / `## Lessons` only. The census found 70 post-mortems in four templates — `## Learnings`, `## Lessons`, level-3 `### Key Lessons`, suffixed `## Recommendations…`, `Symptoms → Lesson`, numbered headings, `Takeaway`, `Prevention` — and only five with no lessons section at all. An exact-match extractor would silently drop most of the corpus.
- **Rules had no required date.** Escape detection (D7) compares a source ticket's closed date with a rule's `Since`; `scripts/validate-standards.mjs` did not require `Since`, so an undated rule could never be flagged.
- **Skills in this plugin all set `disable-model-invocation: true`**, which would stop the future release-prep skill from calling capture.

## The Fix

All in `plugins/auro/skills/capture-standard/` plus small changes to the shared scripts (`git diff fc44ed4..c581b5b`, 12 files, +1293/−17):

- **`scripts/capture.sh`** — every shell step as an `rcs.sh`-style subcommand (`range`, `tickets`, `postmortems`, `sections`, `corpus`, `next-ids`, `open-pr`, `check`, `publish`), passing state through `/tmp/capture_*` files so each step is one allow-listed call.
  - `range` pins both ends to SHAs via `gh api repos/<repo>/compare/<base>...<head>` and prints the run date (used as `Since`). `tickets` collects `AB#` IDs and merged-PR numbers from the range, plus each ticket's ADO closed date.
  - `corpus` reads from `--corpus-ref` (default `main`, D3). `next-ids` counts active, retired and tombstoned IDs and pages every open capture PR over REST for IDs already claimed (D8).
  - `check` fetches the corpus ref's own `validate-standards.mjs` into a private `mktemp -d` and runs it over the corpus with the proposal on top.
  - `publish` builds one commit with the Git Data API (no clone, D5), force-moves `capture/<repo>-<label>` (D6), opens or PATCHes the PR (retargeting its base if `--corpus-ref` changed), and creates a Committed User Story (area `auro-ai`, tag `coding-standards-capture`, current sprint, Hyperlink to the PR) when none exists — reusing one an earlier partial run created (WIQL by title + tag). Every exit ends in one `CAPTURE_RESULT:` line.
  - Security: PRs are matched by owner-qualified head (`AlaskaAirlines:capture/...`) so a fork's same-named branch is never adopted; the ADO PAT reaches `curl` via `-K -` on stdin, not argv.
- **`scripts/locate-sections.mjs`** — deterministic lessons-heading locator (D4): level-agnostic, case-insensitive **prefix** match tolerating numbering, U+2192, an optional `Key`, and `What we learned`; respects fences (including info-string closers), nested headings, CRLF, and HTML comment blocks that open only on a line-start `<!--`.
- **`SKILL.md`** — no `disable-model-invocation`, a narrow description, steps 1–5 read-only, one `AskUserQuestion` confirmation, then publish. Extraction (step 5a) applies a three-test bar; dedupe (5b) runs batch-first then against the corpus with five outcomes (new, merged in batch, source-append, already cited, rejected) each with a reason; source-appends whose ticket closed after the rule's `Since` get an escape stub. A *Calling contract* section defines inputs, the confirmation and the result line for release prep. Grants `Write(//tmp/**)`.
- **`scripts/capture-sections.test.mjs`** — 31 dependency-free cases (`npm run test:capture`, in the PR workflow), one per §2.1 heading variant plus the boundaries; every guard mutation-checked.
- **`scripts/validate-standards.mjs`** — `Since` is required on every active rule (retired rules exempt); two new cases.
- **`scripts/build-copilot-{prompts,agents}.mjs`** — `capture-standard` in `EXCLUDED_SKILLS` (D9); `docs/usage.md` documents the skill.

## Why This Works

- **Prefix, not anchored, heading match.** Anchored, `lessons?( learned)?` misses `9. Lessons for Future AI-Assisted Development`, which is a lessons section. Against the 77 local post-mortems the locator finds exactly the five section-less files the census reports, and the suite pins each variant so a regression fails CI rather than silently dropping lessons.
- **CommonMark's comment rule, not the validator's.** An HTML block only opens when `<!--` starts a line; a mid-line `<!--` is text. Following that exactly keeps commented-out headings hidden without hiding real ones that merely mention `<!--` in inline code.
- **The validator that gates the PR also gates the preview.** `check` runs the corpus ref's own validator, so a malformed proposal fails in chat, and `publish` refuses to write anything that fails it.
- **Re-runs converge instead of duplicating.** One branch per release label, reset (not appended) on each run; the PR is found by owner-qualified head and retargeted to the current corpus ref; the review ticket is reused if a previous run created it. A failed GitHub lookup now stops with `GITHUB_FAILED` instead of reading as "nothing there" and opening a second PR or reusing a claimed ID.
- **Failure is a result, not a crash.** Every `publish` exit prints `CAPTURE_RESULT:`, so a caller can report it and carry on (D12) — capture never blocks a release.
- **The stricter bar keeps the corpus stable.** A candidate must change code, change *what is written* (not how someone investigates), and generalise beyond its component; a rejection names the test it failed. Source-appends keep the rule's wording, adding at most one sentence. On the trial release this rejects about five of the fifteen proposals.
- **Rejected alternatives.** CI-triggered capture (the organisation won't run a model in CI, OQ-6); a clone-and-commit publish (the Git Data API makes "reset to a fresh proposal" a single ref move); paging deeper ADO sprint trees and handling concurrent publishers (not reachable for a once-per-release, one-person run — see Learnings).

## Outcome

- The team now has a skill that turns a release's post-mortems into a reviewable set of proposed coding standards, with a ticket so the review is actually scheduled.
- It has been run end to end — short of writing anything — on a real `auro-formkit` release (`v6.0.2..v6.0.3`), twice: it found the release's seven tickets and seven post-mortems, proposed rules, picked the right new rule numbers, passed its own validation, and wrote nothing when the run was declined.
- It is ready to be plugged into the planned release-prep skill ([AB#1662667](https://itsals.visualstudio.com/E_Retain_Content/_workitems/edit/1662667)).
- Two independent reviews and a re-test during the work found and fixed eleven defects before merge, including three security issues.
- Opening a real pull request and review ticket has not been tried yet; that, and the rest of the proof, is Phase 2b.

- **Rules corpus read from a configurable ref** — `--corpus-ref`; the trials ran against the Phase 1b branch.
- **Each candidate's outcome shown with a reason in the preview and PR body** — five outcomes defined in `SKILL.md` step 5b and the PR-body template; seen in both trials.
- **Escape stub for a source closed after a rule's `Since`** — step 5b escape detection and the PR-body stub naming four failure modes.

**Not Resolved / Partial**
- **New rule IDs never collide** — retired, tombstoned and other open capture PRs' IDs are counted, and a failed read stops the run; two captures allocating at the same moment before either PR exists is an accepted gap (the validator rejects the duplicate before merge).
- **One Committed review story per capture PR, linked both ways, never blocking the PR** — implemented in `publish`, including reuse on re-run, but `publish` has never run live; proven in the 2b round-trip.
- **A capture failure is reported to the caller and never blocks release prep** — the result line exists on every path, but there is no release-prep skill yet to call it (AB#1662667); the callable-by-skill check is in 2b.

## Learnings

- **Follow the spec's parsing rule, not a neighbouring tool's.** CommonMark opens an HTML comment block only on a line-start `<!--`. Reusing the validator's looser "any `<!--` opens a comment" hid auro-ai 1643439's real `## Learnings`, because that post-mortem mentions `<!--` in inline code. Pin such cases with a regression test drawn from the real corpus.
- **Never script file edits with JavaScript `String.replace()` when the replacement text may contain `$`.** In a replacement string, `` $' `` means "text after the match" and `$&` "the match"; a `node -e` edit spliced the rest of `capture.sh` into itself. Use the Edit/Write tools for file edits.
- **A failed lookup must not look like an empty result.** Several `gh` calls swallowed errors, so a network timeout printed a blank commit count followed by `RANGE_OK`, an unreadable PR listing read as "no IDs claimed", and a failed own-PR lookup read as "no PR yet". Check that a value came back and stop with a named error.
- **Make a re-run converge on the state a partial run left behind.** Reset the branch rather than append, retarget the PR's base, and look for a ticket an earlier run created before filing a new one.
- **Claude Code permission paths are gitignore-style.** A single leading `/` is project-relative and `*` does not cross `/`, so `Write(/tmp/*)` covered neither `/tmp` nor its subdirectories; the correct grant is `Write(//tmp/**)`. Verify a grant with a real run outside auto mode.
- **Set the extraction bar before the first trial, not after.** A rule must change code, change what is written, and generalise beyond its component; otherwise one release yields fifteen rules and the corpus churns every release.
- **Independent reviews pay for themselves.** A backup agent review (five findings), Sourcery (two of five fixed), an automated security review (three findings) and a permission re-test (one finding) each caught defects the author's own testing did not. Reply to every bot comment, including the ones deliberately left as-is, with the reason.
- **Test `gh` auth with `gh auth token`, not `gh auth status`.** After a mid-session restart gh/SSH auth lapsed, and `gh auth status` reported inconsistently.

## Iterations That Didn't Work

- **Treating any `<!--` as a comment opener** (first attempt at the backup review's commented-out-heading finding). It hid 1643439's `## Learnings`; replaced with the CommonMark line-start rule, and the case is now pinned in the suite.
- **Editing `capture.sh` with a scripted `node -e` `String.replace()`.** The replacement text contained `` $' ``, which inserted the remainder of the file at the match and corrupted the script. Redone with the Edit tool.
- **`Write(/tmp/*)` as the skill's write grant.** Looked right but matched nothing it needed; replaced with `Write(//tmp/**)` and confirmed in the 2026-10-12 re-test.
- **The original, looser extraction bar.** Two write-free trials on `v6.0.2..v6.0.3` proposed 15 new rules from one release (STYLE-002 and STYLE-005 among them). Tightened on 2026-10-12 and recorded in #57.
- **Deliberately not changed (from Sourcery):** serialising concurrent publishers, recursing into nested ADO sprint trees, and paginating past the contents API's 1,000-entry directory limit. None is reachable for a once-per-release, one-person run against today's repos (largest post-mortem directory is about 40 files); each reply on #60 names the fix if that changes.
